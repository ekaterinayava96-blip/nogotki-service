# Дневник сборки Telegram-бота «Ноготочки»

## ИИ-интеграция: GigaChat (Сбер)

- Провайдер: **GigaChat API** (AI_PROVIDER=gigachat)
- Модель: **GigaChat-2-Pro**
- Авторизация: Authorization Key из проекта GigaChat API → access token (действует 30 мин) → Bearer
- Особенность: эндпоинты GigaChat используют российские корневые сертификаты Минцифры, которых нет в стандартном хранилище Python, поэтому код делает повтор запроса без проверки сертификата (аналогично официальному SDK).

## Шаг 10. База данных

Подключена **SQLite (aiosqlite)**, файл `nogotki.db`. Таблицы: users, services, cart_items, orders, order_items, dialog_history. Услуги загружаются автоматически (6 записей). Память диалога переведена из deque в таблицу dialog_history (лимит 20 сообщений, сохраняется между перезапусками). Вспомогательный модуль `http_client.py` — единый HTTP-клиент с фолбэками «прокси → без SSL» для всех запросов (Telegram/GigaChat/ЮKassa).

## Шаг 11. Корзина

- Добавление услуг с увеличением количества, просмотр корзины с итоговой суммой, удаление позиций.
- Кнопка **«Оформить заказ»**: при пустой корзине заказ НЕ создаётся (бот сообщает об этом).
- Защита от двойного нажатия: после оформления корзина очищается, повторное нажатие видит пустую корзину и блокируется.

## Шаг 12. Тестовая оплата через ЮKassa

- Шаг **«Оплатить»** создаёт платёж в тестовом магазине ЮKassa (shopId + секретный ключ из `.env`) и отправляет ссылку на страницу оплаты.
- Шаг **«Я оплатил»** проверяет статус платежа через API ЮKassa: подтверждает заказ только при статусе `succeeded`, иначе сообщает, что оплата не проведена.
- Повторное нажатие «Оплатить» по оплаченному заказу блокируется, по неоплаченному — переиспользует уже созданную ссылку (повторный платёж не создаётся).
- Реквизиты ЮKassa: тестовые ключи из `.env` (YOOKASSA_SHOP_ID, YOOKASSA_SECRET_KEY).
- **Проверка связки:** первые ключи не подошли (401 «Login has illegal format»), после замены на валидные тестовые ключи платёж создаётся успешно: получены `payment_id` и ссылка `yoomoney.ru/checkout/payments/v2/contract?...`, статус нового платежа — `pending` ✅

## Шаг 13. Автотесты (pytest)

Файл `tests/test_bot_logic.py`, **14 тестов ✅** (`py -m pytest`):
- Корзина: добавление/количество, сумма, удаление, пустая корзина (total = 0).
- Заказы: пустая корзина → заказ не создаётся (None); из корзины с товарами → заказ создаётся, корзина очищается; двойное «оформить» → только один заказ; отметка «оплачено».
- Оплата: классификация статусов (succeeded/pending/canceled); «Я оплатил» при статусе pending НЕ подтверждает заказ; при succeeded — подтверждает.
- История диалога: сохраняется, упорядочена, ограничена лимитом, очищается.

Для запуска тестов требуется pytest.ini с `asyncio_mode = auto` и общим session-loop (иначе ломается изоляция через глобальное соединение aiosqlite).

## Шаг 14. Путь клиента (проверка в бою)

Реально пройден путь клиента в боте @NogotkIcentr_bot:

6. Статус «Оплачен» виден в разделе «Мои заказы»

✅ Полный цикл «запись через оплату» работает: корзина → заказ → платёж → подтверждение статуса → отображение в личном кабинете.
