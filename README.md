# Ноготочки — сервис записи в студию маникюра и бровей

Веб-сервис для записи клиентов: каталог услуг и мастеров, выбор свободного времени,
онлайн-запись, личный кабинет клиента, панель владельца студии. После запуска всё
открывается в браузере по одному адресу — API и веб-интерфейс раздаёт один Node.js-сервер.

Что в репозитории:

| Путь                | Что это                                                        |
|---------------------|----------------------------------------------------------------|
| `backend/`          | **Node.js API + веб-фронтенд** (то, что запускается по инструкции ниже) |
| `prototype/`        | Черновые макеты экранов (не запускаются, справочник)            |
| `docs/`             | Проектная документация и схема БД                               |
| `bot.py` и др. в корне | Отдельный Telegram-бот на Python (не нужен для веб-сервиса)  |

---

## 1. Что установить

Нужен только **Node.js** (внутри него — встроенная SQLite, другие зависимости ставит `npm`).

Требуемая версия Node.js зафиксирована в `backend/package.json` (`engines`):
**22.13 или новее** (рекомендуется 24 LTS). Команды ниже — это npm-скрипты из того же
`package.json`; переменные окружения и их назначение перечислены в `backend/.env.example`
(в development `.env` создавать не нужно — работают дефолты).

- Windows / macOS / Linux: скачайте установщик с https://nodejs.org/ (кнопка LTS) и установите.
- После установки перезапустите терминал (PowerShell/CMD), чтобы PATH обновился.
- Проверьте: `node -v` и `npm -v` должны напечатать версии без ошибок.
- Если `node -v` показал версию **ниже 22.13** (например 20.x или 22.5–22.12) — поставьте свежий
  LTS-установщик с https://nodejs.org/. Сервис использует встроенный модуль `node:sqlite`,
  которого в старых версиях нет: сервер просто упадёт при старте с ошибкой про sqlite.

Git нужен только чтобы получить код: `git clone https://github.com/ekaterinayava96-blip/nogotki-service.git` (или просто откройте уже имеющуюся у вас папку проекта).

## 2. Быстрый старт

Откройте терминал в папке проекта и выполните четыре шага. Все команды — из папки `backend/`:

```bash
cd backend

# 1. Установить зависимости проекта (dotenv, express)
npm install

# 2. Создать структуру базы данных (таблицы)
npm run db:migrate

# 3. Наполнить базу демо-данными: услуги, мастера, клиенты, записи, учётные записи
npm run db:seed

# 4. Запустить сервер
npm start
```

> **Windows PowerShell:** если `npm` выдаёт ошибку про «выполнение сценариев отключено»
> (execution policy), зовите `npm` как `npm.cmd` — например `npm.cmd start`.
> Это особенность PowerShell, а не проекта.

Если всё прошло успешно, в консоли появится строка `API запущен на порту 3000`.

Откройте в браузере: **http://localhost:3000/**

> Важен порядок шагов 2 и 3: `db:seed` требует уже созданных таблиц.
> Если сначала запустить только `npm run db:seed`, он упадёт с ошибкой `no such table`.

## 3. Учётные записи (демо)

Клиентская регистрация на сайте всегда создаёт роль **клиента**.
Учётка владельца в браузере не регистрируется — она заводятся сидом:

| Логин        | Пароль       | Роль     | Что доступно                                      |
|--------------|--------------|----------|---------------------------------------------------|
| `admin`      | `admin12345` | владелец | панель `/admin.html`: статистика, все записи, услуги, мастера |
| `master`     | `master12345`| мастер   | свои записи (мастер «Екатерина»)                  |
| `client`     | `client12345`| клиент   | запись на услугу, личный кабинет, отзывы          |

## 4. Страницы веб-интерфейса

| Адрес            | Назначение                                      |
|------------------|-------------------------------------------------|
| `/`              | Вход / регистрация нового клиента               |
| `/services.html` | Каталог услуг и мастеров                        |
| `/slots.html`    | Свободное время мастера на выбранную дату       |
| `/booking.html`  | Оформление записи (удержание слота → запись)    |
| `/cabinet.html`  | Личный кабинет: мои записи, перенос, отмена     |
| `/admin.html`    | Панель владельца студии                         |

Все страницы черновые (без дизайна) — это тестовая обвязка поверх API.

## 5. API (кратко)

Базовый адрес: `http://localhost:3000/api`

- `GET  /health` — проверка, что сервер жив
- `POST /auth/register`, `POST /auth/login` — регистрация и вход (токен в ответе)
- `GET  /services`, `GET  /masters`, `GET  /studio` — публичный каталог
- `GET  /masters/:id/slots?date=YYYY-MM-DD&service_ids=1` — свободные слоты
- `POST /holds` — удержать слот на время оформления (10 минут)
- `POST /bookings`, `GET/PATCH /bookings[/:id]`, `POST /bookings/:id/cancel` — записи
- `GET/PATCH /admin/stats`, `/admin/bookings`, `/admin/services`, `/admin/masters` — панель владельца

Авторизация — заголовок `Authorization: Bearer <token>`. Цены в API — в копейках
(`price_kopecks`). Время в API — UTC; время салона — UTC+3.

## 6. Частые проблемы

**Порт 3000 уже занят.** Остановите конфликтующий процесс или поменяйте порт:
создайте файл `backend/.env` со строкой `PORT=3001` и открывайте `http://localhost:3001/`.
Образец всех настроек — `backend/.env.example`.

**`npm start` падает с ошибкой про node:sqlite или «неизвестный модуль sqlite».**
Версия Node ниже 22.13 — обновите до свежего LTS (https://nodejs.org/).

**`npm` не найден.** Node установлен, но терминал открыт со старым путём —
закройте и откройте терминал заново (или перезапустите компьютер после установки).

**Вход не работает.** Учётные записи появляются только после `npm run db:seed`
(шаг 3). Если базу сбросили — повторите шаги 2–3.

**База не создаётся / ошибки таблиц.** Убедитесь, что выполнен `npm run db:migrate`
перед `npm run db:seed`.

## 7. Сброс базы данных

Очистить и пересоздать всё заново (миграции + чистый сид):

```bash
npm run db:reset   # удаляет файл БД и применяет все миграции
npm run db:seed    # демо-данные заново
```

Файл базы: `backend/data/nogotki.db`. Он и его служебные файлы не попадают в git.

## 8. Тесты

Автотест сценариев (роли, записи, отзывы, безопасность) написан на Python и проверяет
логику напрямую по SQL. Если Python установлен, запустите **из корня репозитория**
(не из `backend/`):

```bash
py -3 -X utf8 backend/tests/test_role_scenarios.py
```

Ожидаемый результат: `ИТОГ: 45 OK, 0 FAIL`.

## 9. Структура `backend/`

```
backend/
├── src/
│   ├── index.js          # точка входа (запуск сервера)
│   ├── app.js            # Express-приложение, маршруты, статика, 404
│   ├── config.js         # настройки (порт, путь БД, окружение)
│   ├── startup.js        # миграции при старте, graceful shutdown
│   ├── routes/           # обработчики API (auth, catalog, holds, bookings, admin, feedback)
│   ├── repo/queries.js   # слой доступа к данным (SQLite)
│   ├── lib/              # валидация, время, пароли, доступность слотов
│   ├── middleware/       # авторизация, rate limit
│   └── db/               # миграции, сид, управление БД
├── public/               # черновой веб-фронтенд (страницы + js + css)
├── tests/                # Python-автотест сценариев
├── data/                 # файл базы данных (создаётся при старте)
├── .env.example          # образец настроек
└── package.json          # зависимости и npm-скрипты
```
