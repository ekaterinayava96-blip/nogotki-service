# Правила вёрстки фронтенда

1. **Верстаем обычными HTML, CSS и JS, без сборщиков и фреймворков.** Так же, как сделан черновой фронт `backend/public`.

2. **Один экран прототипа — одна страница в папке `web/`.**

3. **Все обращения к серверу идут через `web/js/api.js`.** Внутри страниц запросов быть не должно.

4. **Цвета, шрифты и размеры берём только из `web/tokens.css`.** Новых значений не добавляем.

5. **Папку `server/` не трогаем.** Если для экрана не хватает данных — сначала говорим об этом, а не подбираем сами.

6. **Папку «Прототип» не меняем и не переименовываем** — она только образец.

7. **Ошибку от API показываем клиенту текстом на экране**, а не только в консоли.

8. **Экраны мастера и администратора пока не верстаем.**

---

Перед вёрсткой нового экрана смотрим его строку в карте: [`docs/ui-map.md`](ui-map.md). В ней указаны файл прототипа, что экран показывает клиенту, какие эндпоинты дают данные и какие вызывают кнопки, и куда ведут переходы.
