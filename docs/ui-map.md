# Карта клиентских экранов «Ноготочки» (для вёрстки)

Источники: кликабельный прототип `prototype/` (SPA: 5 страниц, экраны-состояния рендерятся `app.js`),
черновой фронт `backend/public/`, код API `backend/src/routes` (папки `server/` в репозитории нет — сервер в `backend/`).

Как читать столбец «Файл»: `prototype/…` — экран уже есть в прототипе; `backend/public/…` — экран есть только в черновом фронте;
`—` — файла нет нигде, экран придётся верстать с нуля (но он нужен по ТЗ).

Покрыты ТОЛЬКО клиентские экраны. Панель мастера/владельца (`prototype/admin.html`, `/api/admin/*`) сюда не входит.

> По разбору пробелов данных (раздел внизу) из вёрстки убраны: фото услуг, индикатор занятости дня, форма ввода контактов,

## Расхождения и решения (бэкенд не трогаем — всё решаем на стороне экрана)

### 1. Экрану не хватает данных

| Находка | Решение | Почему |
|---|---|---|
| Лендинг — фото услуг | Убрать элемент из вёрстки | `GET /api/services` фото не отдаёт (`services.photo_path` в сиде NULL), каталог читается и без картинок; фото мастеров остаются — их отдаёт `GET /api/masters`. |
| Календарь записи — индикатор «занятости дня» | Убрать элемент из вёрстки | `GET /api/masters/:id/slots` отдаёт только свободные слоты, занятость дня API не знает — признак декоративный. |
| Шаг «Контакты» — поля «Имя»/«Телефон» | Значение брать из API, текст экрана привести к нему | Имя/телефон — данные аккаунта (`POST /api/auth/register`, обязательные `name`/`phone`; `client` в `POST/GET /api/bookings`) → показываем read-only «запись оформляется на: …». |
| Экран «Профиль» | Убрать элемент из вёрстки | Эндпоинтов чтения/правки профиля нет, сценарий записи проходит без него. |
| Экран «Уведомления» | Убрать элемент из вёрстки | Напоминание за 24 часа — функция бота, уведомлений в API/БД нет. |

### 2. Эндпоинт есть, экрана нет

| Находка | Решение | Почему |
|---|---|---|
| `POST/GET /api/feedback` (отзывы) | Добавить кнопку на существующий экран | Эндпоинты рабочие (`backend/src/routes/feedback.js`), паспортная функция «отзывы»: блок «Оставить отзыв» на экране кабинета (№22). |
| `PATCH /api/bookings/:id` (перенос) | Добавить кнопку на существующий экран | Перенос нужен клиенту; кнопка «Перенести» уже есть в черновике кабинета (№23). |
| `POST /api/auth/logout` (выход) | Добавить кнопку на существующий экран | Кнопка «Выйти» уже стоит на всех страницах черновика (№18). |
| `POST /api/bookings/:id/cancel` (отмена) | Добавить окно подтверждения | Отмена необратима, а прототип снимает запись сразу, без вопроса (`prototype/app.js:469`). |
| `DELETE /api/holds/:id` (снятие удержания) | Оставить как есть | Удержание снимается автоматически через 10 минут или при создании записи — кнопка клиенту не нужна. |
| `GET /api/bookings/:id` (деталь записи) | Оставить как есть | Клиент смотрит свои записи списком (`GET /api/bookings`, №13); перезапрос на успех-экране — опция фронта. |
| `GET /health` | Оставить как есть | Служебный для мониторинга/деплоя, клиенту не показывается. |

### Что на стороне экрана решить нельзя

- Вывод фото услуг (данных нет в API);
- индикатор занятости дня (API не отдаёт);
- редактирование контактов и профиля (эндпоинтов профиля нет);
- напоминание за 24 часа (функция бота, данных нет).

Каждый из них закрыт удалением блока/экрана из вёрстки (см. таблицы выше) — правок API не требуется.
