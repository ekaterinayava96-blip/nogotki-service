# Сборка в контейнере и запуск на сервере

Сервер на сервере собирает образ заново при каждом обновлении, и всё, что было
внутри контейнера, при этом пропадает. Единственное, что переживает
пересборку, — том, подключённый снаружи. Поэтому база лежит в отдельном
каталоге, путь к ней задаётся настройкой `DB_PATH`, и этот каталог
подключается к контейнеру как том.

Инструкция для обычного сервера без Docker описана в [`deploy.md`](deploy.md).
Здесь — вариант с контейнером.

---

## 1. Что где лежит

| Что | Где в контейнере | Переживает пересборку |
|-----|------------------|------------------------|
| Код бэкенда | `/app/backend/src` | нет |
| Фронтенд | `/app/web` | нет |
| Зависимости | `/app/backend/node_modules` | нет, ставятся при сборке |
| Файл базы | `/data/nogotki.db` | да, если подключить том |
| Копии базы | `/data/backups/` | да, там же |
| Настройки | переменные окружения, не файл | задаются при запуске |

Путь к базе не зашит в код: `DB_PATH` читается в `backend/src/config.js`,
по умолчанию `data/nogotki.db` (то есть рядом с кодом — для локальной
разработки), а в образе переопределён на `/data/nogotki.db`. Бэкапы
прикладываются к каталогу базы автоматически (`backend/src/db/backup.js`),
отдельной настройки не требуют.

---

## 2. Сборка образа

Собирать из **корня репозитория**, не из `backend/`: контекст сборки должен
включать и `web/`, потому что сервер отдаёт фронтенд из каталога уровнем выше.

```bash
docker build -t nogotki .
```

Тег образа полезно ставить с датой или номером сборки — так проще откатиться:

```bash
docker build -t nogotki:2026-10-12 .
```

### Проверить, что тег Node существует

Версия Node зафиксирована в `Dockerfile` (`node:26.10.0-slim`) и совпадает с
локальной. Если сборка падает на `manifest unknown`, тега нет — тогда замените
на `node:26-slim` (плавающий минор) или на конкретный, существующий.

### Что не попадает в образ

Список — в [`.dockerignore`](../.dockerignore) в корне репозитория. Главное
из него:

| Исключено | Зачем |
|-----------|-------|
| `node_modules` | Ставится при сборке через `npm ci`, иначе внутрь попадут модули для вашей машины |
| `*.db`, `backend/data` | **Локальная тестовая база не должна попасть на сервер** — иначе она затрёт настоящую |
| `.env`, `.env.*` | Секреты задаются на сервере отдельно |
| `.git` | История изменений в образе не нужна |
| `docs`, `prototype`, `*.md` | Не нужны в рантайме |

Проверить, что в образ не проскочило ничего лишнего:

```bash
docker run --rm --entrypoint sh nogotki -c "ls -la /app/backend/data 2>/dev/null; ls /app"
```

`backend/data` в образе отсутствует, `.env` тоже. Если они есть — сборка идёт
не из того каталога или `.dockerignore` не на месте.

## 3. Подключение папки с базой

Том создаётся один раз и переиспользуется при всех следующих запусках:

```bash
docker volume create nogotki-data
```

Имя можно любое, но постоянное: новый том — пустая база, и все записи, что
были, исчезнут из сервиса.

Права на папку хоста, если монтируете каталог, а не именованный том:

```bash
mkdir -p /srv/nogotki-data
sudo chown -R 1000:1000 /srv/nogotki-data   # uid:gid пользователя node в образе
```

При bind-монтировании права выставить нужно один раз: том из образа
наследует владельца сам, а папка хоста — нет.

## 4. Запуск

```bash
docker run -d \
  --name nogotki \
  --restart unless-stopped \
  -p 3000:3000 \
  -v nogotki-data:/data \
  -e PORT=3000 \
  -e DB_PATH=/data/nogotki.db \
  -e TRUST_PROXY=1 \
  nogotki
```

`--restart unless-stopped` — контейнер поднимется сам после перезагрузки
сервера. Порт 3000 наружу можно не открывать, если перед контейнером стоит
nginx (см. раздел 6).

Проверка:

```bash
docker ps                                   # статус Up (healthy)
docker logs nogotki                         # миграции и «API запущен на порту»
curl -s http://127.0.0.1:3000/health        # {"status":"ok"}
```

---

## 5. Обновление

```bash
git pull
docker build -t nogotki:новая-дата .
docker stop nogotki && docker rm nogotki
docker run -d --name nogotki --restart unless-stopped \
  -p 3000:3000 -v nogotki-data:/data \
  nogotki:новая-дата
```

Том `nogotki-data` подключается заново и переживает удаление контейнера —
данные на месте. **Пересоздавать том нельзя**, это равносильно удалить базу.

Откат: запустите предыдущий тег образа с тем же томом.

## 6. nginx и HTTPS

Настройки те же, что в [`deploy.md`](deploy.md), раздел 7, только вместо
`systemd` контейнер. Ключевое: проксировать на порт, который отдан
`-p 3000:3000`, и оставить `TRUST_PROXY=1`, иначе ограничение попыток входа
будет видеть адрес прокси, а не клиента.

```bash
sudo certbot --nginx -d nogti.com.ru
```

## 7. Миграции применяются сами

Отдельную команду на сервере набирать не нужно. При каждом старте приложение:

1. проверяет настройки (`src/config.js`) — при `NODE_ENV=production` без
   `DB_PATH` старт падает сразу, с понятным сообщением;
2. применяет миграции из `backend/src/db/migrations/*.sql` в алфавитном порядке;
3. только затем открывает порт и начинает отвечать.

Порядок «миграции раньше порта» в коде явный: `boot()` вызывается до
`app.listen()` в `backend/src/index.js`. Так сервер не может отдать запрос к
схеме, которой ещё нет.

Повторно уже применённые миграции не выполняются: имена файлов пишутся в
таблицу `schema_migrations`, и при следующем старте они печатаются как
`skip <файл>`. Обычный вывод при обновлении:

```
skip   001_init.sql
skip   002_add_users_client_role.sql
...
apply  013_что-то_новое.sql
Стартовая подготовка завершена (NODE_ENV=production).
API запущен на порту 3000 (NODE_ENV=production).
```

Проверить, что миграции не падают, отдельно от контейнера (без базы и без
HTTP-сервера):

```bash
docker run --rm -v nogotki-data:/data -e NODE_ENV=production \
  -e DB_PATH=/data/nogotki.db nogotki npm run start:check
```

## 8. Если что-то не запускается

| Симптом | Причина | Что делать |
|---------|---------|------------|
| `manifest unknown` при сборке | Нет тега `node:26.10.0-slim` | Заменить на `node:26-slim`, затем `docker pull` |
| `[config] DB_PATH обязателен` | Не передан `-e DB_PATH=/data/nogotki.db` | Добавить переменную при запуске |
| `SQLITE_CANTOPEN` или нет прав | У папки хоста не тот владелец | `chown -R 1000:1000 /srv/nogotki-data` |
| Старт падает, в логах `apply 0xx` | Миграция не прошла | Смотреть `docker logs nogotki`; состояние базы откатится транзакцией |
| Данные пропали после обновления | Создан новый том | Использовать постоянное имя `nogotki-data` |
| `no such table` при запросах | Порт открылся раньше миграций — так быть не должно | `docker logs nogotki`: должны быть строки `apply`/`skip` до «API запущен» |

Журналы:

```bash
docker logs -f nogotki        # живой вывод
docker logs --tail 100 nogotki
docker inspect nogotki        # состояние, монтирования, порты
```
